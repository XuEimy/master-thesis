# 长期记忆使用说明

建立日期：2026-10-23。来源项目：个人回忆唤起研究。

## 1. 采用的方式

本项目采用 [Engramory](https://github.com/tinqiao-oss/engramory) 的文件式记忆协议，并结合本机已有的“项目记忆与 Obsidian 跨项目索引分层”工作方式。

参考实现固定于上游提交 `500cf5d49a19108196a420bd50e71ef0a3a80e7c`，项目内保留协议、工具与 MIT 许可。该提交标识用于说明本次引入来源，不表示未来一直是最新版。

采用 Codex 的基础接入：`AGENTS.md` 工作规则、项目内协议和检查脚本。未安装生命周期钩子；没有后台服务或自动抓取聊天的进程。记忆整理由执行任务的代理实际读取、判断和写入，校验脚本检查结构与容量，不判断内容真假。

## 2. 各层职责

| 位置 | 用途 | Git 同步 |
|---|---|---|
| `docs/` | 可阅读的选题、指导整理及框架，作为项目文档基线 | 是 |
| `AGENTS.md` / `CLAUDE.md` | 开始工作及维护记忆的规则 | 是 |
| `.agents/skills/engramory/` | 协议、模板及检查工具 | 是 |
| `.engramory-memory/MEMORY.md` | 简短索引，只列笔记入口 | 否 |
| `.engramory-memory/*.md` | 当前研究接续所需的压缩笔记、外部位置等 | 否 |
| 本机 Obsidian `Codex Memory` | 跨项目发现入口和稳定事实 | 使用本机既有管理方式 |

项目内只有一个代理记忆目录。正式文档保留完整论述，记忆只保留恢复工作所需信息，不复制整份研究文档或聊天。Obsidian 只增加本项目入口与起点约定，不另存第二套框架。

## 3. 开始新对话

在本项目目录打开聊天，代理先读取 `AGENTS.md`，再读取 `.engramory-memory/MEMORY.md`，按需打开相关笔记。研究任务优先读取项目接续笔记，并核对其指向的正式文档。

可以直接说：“继续个人回忆唤起研究，先读取项目规则和记忆，接着做记忆线索与记录需求框架。”

Codex 不会因为目录名叫 MEMORY 就自动注入内容；需要规则触发实际文件读取。首次在新路径开聊时应核对读取情况。本次已验证文件、链接和校验工具；未来会话是否实际遵守规则，以该次真实读取为准。

## 4. 更新规则

- 只有长期有效的决定、约束、可复用方法和接续研究所需信息才进入记忆。
- 先查重、再更新已有笔记；同一研究任务至多保留一份当前接续笔记。
- 正文使用中文。元数据类型及 `Why:`、`How to apply:` 等协议字段保留英文，以兼容校验工具。
- 写明日期和来源。当前确认、候选推论、待核实事实要明确区分。
- 新的明确决定优先，旧决定如被替代，记录替代原因或移入 `archive/` 并修正索引。
- 不保存完整原始对话、凭证、临时调试记录或 Git 实时状态。
- 项目文档已经说明的内容不在记忆中完整复制；需要接续时保留稳定文件位置并现场核对。
- 写入串行进行；避免多个代理同时修改同一记忆库。

## 5. 校验

在项目根目录执行：

```sh
python3 .agents/skills/engramory/tools/engramory_check.py .engramory-memory/MEMORY.md
python3 .agents/skills/engramory/tools/engramory_doctor.py .engramory-memory
```

索引软限为 150 行或 20 KB，硬限为 200 行或 25 KB；超过前先合并和归档。这里通过规则和显式校验落实，没有安装会阻止所有写入的硬性拦截器。

## 6. 在另一台电脑恢复

先克隆仓库并阅读 `README.md` 和 `docs/`。初始化本机记忆：

```sh
python3 .agents/skills/engramory/tools/engramory_init.py codex --project-root .
```

此命令创建本机索引并接入规则，不会自动重建研究记忆。随后让代理根据正式文档整理一份当前研究接续笔记，并运行两项校验。已有本机记忆时先读取、核对和合并，不覆盖已有结论。

本项目的记忆根目录被 `.gitignore` 排除。GitHub 保存正式文档与规则；需要保留本机接续细节时，另行通过用户选定的本机备份方式保存 `.engramory-memory/`。Obsidian 入口使用本机路径，换机需重新核对。
